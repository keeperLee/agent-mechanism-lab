# Agent 机制可视化实验室

一个**纯静态、零依赖、不需要 API Key** 的站点，用可操作、可回放的方式讲清 AI Agent 的三处内部机制：

| # | 实验室 | 它回答的问题 |
| --- | --- | --- |
| 01 | **ReAct 循环** | 模型在哪一步才「看到」工具结果？Observation 到底是谁写的？ |
| 02 | **上下文预算** | 窗口被什么吃掉了？撑爆的时候会发生什么？ |
| 03 | **检索与融合** | 两路召回结果不一样该信谁？RRF 为什么只用名次不用分数？ |

在线地址：https://keeperlee.github.io/agent-mechanism-lab/

配套的阅读型课程：[Agent 学习平台](https://github.com/keeperLee/agent-learning-platform)。本实验室是它的动手侧补充 —— 那边讲「应该怎么做」，这里讲「它到底怎么跑的」。

## 先说清楚：哪些是真算的，哪些是预置的

这一点比功能列表更重要。本站是纯静态站点，**页面上不会真的调用大模型**，所以必须把边界讲明白：

| 内容 | 性质 |
| --- | --- |
| ReAct 执行轨迹（模型输出、工具返回） | **预置的真实形态数据**。完整、自洽、参数合法，但不是实时推理 |
| BM25 打分、同义词扩展、RRF 融合 | **浏览器里真实计算**。改参数结果就变 |
| 上下文 token 占用 | **估算**，见下 |
| 时间线与预算条的可视化 | 由上面两项实时驱动，非硬编码数字 |

**为什么不接后端。** 接一个真模型 API 需要密钥与服务端代理，那就不是静态站点了，也没法部署到 GitHub Pages。与其造一个假的聊天框，不如把真实形态的数据摊开来讲机制。

**token 是估算，不是精确计数。** 精确计数需要具体模型的分词器词表（几百 KB 到几 MB），与零依赖的前提冲突。本站按字符类别估算：

- CJK / 全角字符 ≈ 1 token / 字
- 英文数字串 ≈ 1 token / 4 字符
- 空白与标点 ≈ 1 token / 3 字符

误差常在 ±20% 以内。所以界面上所有 token 数字都带「估算」标注，**只用于比较不同构成的相对开销**（例如「工具定义占了多大比例」），不适合对外报数。估算器在 `assets/js/tokens.js`，方法写在文件头。

**语义通道的替身。** 实验室三里代表「向量检索」的那一路，其语义泛化能力来自一张**手工维护的同义词表**（`assets/js/data/corpus.js` 的 `SYNONYMS`），而不是 embedding 模型。算法本身是真实的 tf-idf 余弦，只是「语义知识」的来源不同。要接真实向量库，只需替换 `searchSemantic` 一个函数 —— 融合层的数学完全不用动。

## 实验室一览

### 01 · ReAct 循环单步执行与回放

两条预置轨迹，逐步播放：

- **起点** —— 循环开始前的窗口：系统提示、本轮提供给模型的工具清单（含各自的 token 开销）、用户提问
- **正常路径** —— 订单延误与退款咨询，4 步
- **错误恢复** —— 模型把 `range` 参数写成了 `30days`，工具返回结构化错误，模型据此自我修正。整个恢复过程用户无感

**舞台一次只渲染当前这一步**，不把整条循环铺成长页：

- 模型输出在左、工具返回在右**并排**，一次请求与一次响应直接对上因果关系
- 顶部轨道吸附在视口顶部，右上角显示「第 N / M 步」，点任意节点可跳转
- 支持 `←` `→` 键切换
- 长 JSON 有高度上限（随视口自适应），不会单独把页面撑长
- 窄屏下正文排在控制面板之前

侧边栏实时显示上下文累积，把「系统提示与工具定义是每一轮都要重发的固定开销」这件事算出来给你看。

### 02 · 上下文预算可视化

六段构成（系统提示 / 工具定义 / 检索片段 / 对话历史与工具返回 / 当前提问 / 输出预留）堆叠成一条窗口占用条。可以拖的：

- 四个窗口档位（8K / 32K / 128K / 256K）
- 逐个开关工具定义，实时看到「每一轮的重发成本」怎么变
- 检索片段数、对话轮数、每轮工具返回体积、输出预留
- 三档预设：**极简 / 均衡 / 塞满** —— 「塞满」会真的把窗口撑爆，并给出取舍建议

页面上明确区分了**实测**（系统提示、工具定义、当前提问）与**按样本推算**（检索片段、对话历史），不把两者混为一谈。

### 03 · 两路召回与 RRF 融合

14 段语料，真实运行的 BM25 与语义余弦并排对比，再用 RRF 融合，并把 `1/(k+rank)` 的加法逐项摊开。

两个刻意保留的观察点：

- 查「幻觉怎么缓解」时，BM25 只找到 1 篇（字面含「幻觉」），语义通道找到那篇只用「编造」「不实」的文档。融合把它拉到第 2 名 —— **这是融合价值的直观体现**。
- 查「怎么降低费用」时，BM25 把一篇只在结尾提了一句费用的文档排到第 1，而融合把它压回第 3 —— **这是 BM25 的真实缺陷，不是 bug**。

还可以切换「朴素分数相加」做对照，看归一化如何改变结论。

## 技术实现

零依赖、无构建步骤。仓库本身就是产物。

| 关注点 | 做法 |
| --- | --- |
| 中文分词 | 字符二元组（bigram）+ 停用词表 + 虚词字符过滤 |
| BM25 | k1=1.2、b=0.75，IDF 用 `ln(1 + (N-df+0.5)/(df+0.5))` |
| RRF | `score = Σ 1/(k + rank)`，k 默认 60（原论文取值），界面可调 |
| 主题 | CSS 变量 + `data-theme`，在引入样式**之前**定下，不闪白 |
| 路由 | hash 路由，切页时卸载上一个实验室（实验室一有定时器，必须清） |

## 本地运行

需要 Node.js >= 22.13（用到了内置 WebSocket，交互回归测试依赖它）。

```bash
npm run dev
```

打开 http://127.0.0.1:5173/。

> 不能直接双击 `index.html`：本项目用了 ES Module，`file://` 下会被 CORS 拦住，必须走 HTTP。

## 命令

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动本地静态服务器（零依赖） |
| `npm run validate` | 内容、结构与**算法自检**（CI 用的同一个脚本） |
| `npm run e2e` | 浏览器交互回归测试（需要本机有 Chrome / Edge / Chromium） |

## 校验都在查什么

`npm run validate` 不只是查文件在不在，它还**真的执行算法并断言结果**：

| 分组 | 检查项 |
| --- | --- |
| 关键文件 | 20 个必需文件存在且非空 |
| 页面结构 | 挂载点齐备；主题脚本必须在引入样式之前（否则深色模式闪白）；本地资源引用全部存在 |
| 实验室注册 | app.js 声明的容器 id 必须与实验室模块实际查询的一致 —— 不一致时页面不报错，只是空白 |
| token 估算 | 中英文字符比例、空输入、非字符串输入、单调性 |
| 检索算法 | 分词是否剔净停用词与跨虚词碎片；BM25 是否按键值降序且无 NaN；同义词扩展是否**双向**；RRF 算术是否精确（含 `(1,2)` 与 `(2,1)` 必须等分这一对称性）；归一化是否除零 |
| 教学行为 | 两路召回必须能分叉、融合必须把独家命中的文档拉进前列、语料 id 不得重复 —— **这几条被改坏时页面看起来正常，但已经不教东西了** |
| 轨迹数据 | 步骤完整、工具名与必填参数合法、枚举值合规、均以 final 收尾 |
| 预算数据 | 窗口档位递增、工具集与轨迹是同一份引用（两个实验室必须讲同一个 Agent） |
| 样式类名 | 实验室模块用到的类名在 CSS 中都有定义 |

`npm run e2e` 用 CDP 驱动真实浏览器，覆盖静态检查查不到的行为：实验室能否真的挂载、拖参数后数字有没有变、切页时定时器有没有泄漏、主题能否跨刷新保持、全程有没有未捕获异常。找不到浏览器时返回码为 2，CI 会当作跳过。

其中几条是针对**布局退化**的，因为它们靠肉眼很容易被当成缩放或环境问题放过去：

- **单步聚焦下页面高度必须基本不随步数变化** —— 这条锁住的就是「步骤太长、不方便查看」这个缺陷
- 任意一步都只能有一个详情卡，不随步数堆积
- **窄屏下不得横向溢出**，且容器的左右内边距不能被 `padding` 简写清零
- 窄屏下正文必须排在控制面板之前

> 测试会显式设定 1280×900 的桌面视口。无头浏览器默认 800×600，窄到会触发响应式折叠，让「左右并排」这类断言失败 —— 而失败原因和被测代码毫无关系。

## 想接着改

- **换成真实向量检索**：改 `assets/js/bm25.js` 的 `searchSemantic`，让它去查你的向量库。融合层不用动。
- **加一条轨迹**：往 `assets/js/data/traces.js` 的 `TRACES` 里追加，校验脚本会检查步骤完整性与参数合法性。
- **扩充检索语料**：往 `assets/js/data/corpus.js` 的 `CORPUS` 里加片段，并保证 id 唯一 —— 校验会拦重复，也会检查「两路召回仍能分叉」这个教学前提。
